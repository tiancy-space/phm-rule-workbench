# 组件与技术栈评估

对照用户给出的前端参考栈，说明每个组件在本项目里怎么用，以及原型里哪些交互这套组件覆盖不了、最后怎么补。

参考版本：Vue ^2.6.10、Vue Router ^3.1.3、Vuex ^3.1.2、Element UI ^2.13.0、Vue CLI ^4.1.0、TypeScript ~3.5.3、Axios ^0.19.1、ECharts ^5.1.0、vue-i18n ^8.15.3。

后端不在那张表里，按任务要求用 JDK 8 + Spring Boot 2.7.18 + MyBatis-Plus 3.5.5。接口文档用 springdoc-openapi 1.7（OpenAPI 3）。springfox 已经停更，和 Boot 2.7 也不好配，所以没有用它。

## TypeScript 为什么没有铺到页面

Vue 2.6 的 class 组件或 `vue-property-decorator` 要额外一套写法，Element UI 2 的类型定义在 TS 3.5 上不完整，属性提示经常是 `any`。把全部页面改成 TS 会拖慢功能对齐，类型也帮不上忙。

因此：

- 页面、路由、Vuex、接口封装用 JavaScript；
- 保存故障、预览表达式这些核心请求体写在 `frontend/ts/api-types.ts`；
- `npm run typecheck` 用 `tsc --noEmit` 检查这份契约。

## 原型能力与组件的差距

### 梯形图

Element UI 没有继电器梯形图。ECharts 的图类别也不适合「串联 = 且、并联 = 或」这种电气图。

处理：后端把组合式解析成展示树（`display`），前端 `src/utils/ladder.js` 按原型的触点算法自己画 SVG（母线、串联、并联、线圈、可折叠的命名组）。大图组件 `BigCanvas.vue` 负责滚轮缩放、拖拽平移、适应窗口、100%，以及导出 SVG / 2 倍 PNG。快捷键 `+` `-` `F` `0` `Esc` 与原型一致。

没有引入 JointJS 或 AntV X6。电气梯形图不是普通节点连线，通用图库排出来不像原型。

### 流程图

同样不适合用 ECharts 或 Element 画。处置步骤有五种形状，箭头上是分支名，并且要避免交叉。

处理：`src/utils/flowSvg.js` 移植原型的生成树。广度优先展开，已经画过的步骤不再拉回边，改成「↪ 转至」虚线框；同一层用水平母线分叉。没有被任何分支指到的步骤单独成一棵树，左上角红字「⚠ 不可达（无分支指向）」。未配置出口画成红色「✕ 未配置出口」。

没有引入 dagre。dagre 会把回边画成真正的连线，交叉正是原型要避开的。自绘布局和 Vue 2 没有版本冲突，也不增加包体。大图同样走 `BigCanvas.vue`，点击节点会关掉大图并定位到该步骤。

校验结果放在流程头下方，和原型一样用可展开的色块：红色阻断项、黄色提示。通过且没有提示时是一行绿字。

### 零 JSON 表达式编辑

不需要 Monaco。组合式是很短的 `A1 & (A2 | A3)`，用文本框加按钮插入代号即可。语法检查、展开、中文释义、反解析全部走后端，前端只展示返回的规范写法和出错位置。这样前后端不会各写一套解析器。

### 试跑曲线

ECharts 折线图够用。统计值（最小、越限时长等）由后端按原型算法算好，前端不自己重算，避免和 Java 求值分叉。

### 拖拽排序

步骤卡片左侧是 `⋮⋮` 拖拽手柄，用浏览器原生拖放，不另引 Sortable。松手后调用 `POST /api/flows/{id}/steps/reorder`。上移 / 下移仍保留。排到第一位的步骤就是起点，出口仍按步骤主键连。

### 国际化

vue-i18n 已接入，但手册和原型全是中文，没有第二套语言要翻。字典的中文名来自 `t_phm_dict_item`，不写死在前端。

## Axios 0.19 的安全公告

按要求保持 0.19.x，当前锁定 `0.19.2`。这个版本有公开漏洞，正式对公网开放前应单独评估后再升：

- [GHSA-wf5p-g6vw-rhxx / axios#3410](https://github.com/axios/axios/pull/3410)：跟随重定向时可能把请求头带到别的主机。0.21.1 起修复。
- 更早的 0.19 还受 [CVE-2020-28168](https://nvd.nist.gov/vuln/detail/CVE-2020-28168) 影响（SSRF 向的请求头泄露），同样在 0.21.1 修复。

本工作台的 Axios 只请求构建期写死的 `VUE_APP_API_BASE`，不把用户输入当成请求地址，风险主要在「如果以后有人用这份客户端去请求不可信 URL」。升级建议：业务确认后把 `axios` 升到 `0.27.2` 或 `1.x`，并回归请求头、错误体和文件下载。这次没有改版本。

## 登录

本期不做登录，也没有会话。写操作的审计人只读请求头 `X-Operator`，不传就是 `system`。网关或反向代理如果要区分操作者，在转发时加上这个头即可。前端不会弹出登录框，也不会保存口令。

## 第三轮对齐

### 已经按原型补上的

- 模拟试算：每个测点显示中文参数名、单位和 `编码 · 来源`。枚举型参数用下拉，选项来自 `t_phm_rule_param_meta.enum_dict`（`0:名称;1:名称`），并保留「缺失 / 无效」。数值和字符串仍是输入框。时间窗按「函数 · 同车 N 秒内 / 出现过关联故障」勾选。结果是「判定依据 / 通过」表。现有 `GET /api/params` 已经带齐这些字段，没有另加接口。
- 通用前置：编辑区改成一排可点击芯片。蓝底是继承生效，琥珀色划线是豁免。点击即切换，保存后写入豁免表。适用范围仍是「启用，且车型、来源盖得住当前故障」。
- 司机 / 专家视角：右侧改成左右分屏。左边是专家处置单（当前步骤、数据卡窗口说明、确认项、分支按钮、时间线），右边是司机车载屏。操作步骤选择「成功」之前，确认项必须全部勾选，否则提示「请先勾选全部确认项（专家代录司机反馈）」并不前进。「未成功」不受这条限制。视角预览没有实时数据，判断步骤只展示条件说明。
- 命名组编辑弹窗：预览接口多返回展示树 `display`。弹窗按这棵树画实时分组清单（组名、满足其一 / 同时满足、且或药丸、叶子中文），并保留规范写法和展开式。

### 仍未对齐

- 登录不做，见上一节。

## 第四轮对齐

历史故障试跑和视角预览共用 `FlowRunner`。试跑保留事件选择、单步、自动运行、数据卡统计、小曲线和系统预判；改判仍要填写理由。操作步骤选「成功」前必须勾完确认项，和视角预览同一句提示。自动运行和单步会按原型先视为确认项已勾选，再采用预判或事件里记录的答案。

步骤详情抽屉拆成四个页签：基本信息、数据卡、判断与分支、确认项。数据卡的统计项改成勾选，数值卡可以设越限和曲线，状态卡可以设目标值。判断步骤可以套用「是 / 否」「正常 / 异常」，分支条件可以选择数据卡、原子或命名组。司机动作放在确认项页签。抽屉顶部可以上一步 / 下一步。

积木池分成参数元数据、原子规则、命名组。参数加为数据卡；在判断步骤上，原子和命名组可以「设为判断条件」，写到第一条人工分支，并在没有「否则」时补一条。

登录仍然不做。
