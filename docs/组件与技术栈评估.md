# 组件与技术栈评估

对照用户给出的前端参考栈，说明每个组件在本项目里怎么用，以及原型里哪些交互这套组件覆盖不了、最后怎么补。

参考版本：Vue ^2.6.10、Vue Router ^3.1.3、Vuex ^3.1.2、Element UI ^2.13.0、Vue CLI ^4.1.0、TypeScript ~3.5.3、Axios ^0.19.1、ECharts ^5.1.0、vue-i18n ^8.15.3。

后端不在那张表里，按任务要求用 JDK 8 + Spring Boot 2.7.18 + MyBatis-Plus 3.5.5。接口文档用 springdoc-openapi 1.7（OpenAPI 3）。springfox 已经停更，和 Boot 2.7 也不好配，所以没有用它。

## 实际采用的版本

| 组件 | 锁定版本 | 怎么用 |
|---|---|---|
| Vue | 2.6.14 | 工作台和处置流程都是单文件组件。锁 2.6.14 而不是 2.7，是为了和 `vue-template-compiler` 2.6.14 成对，避免构建期版本不一致 |
| Vue Router | 3.1.6 | hash 模式，只有工作台一个路由。处置流程是全屏浮层，不另开路由，这样静态托管不用配回退 |
| Vuex | 3.1.3 | 只存「处置流程是否打开、当前要定位的故障」。底账、原子、流程内容都从接口取，不在前端再存一份会过期的副本 |
| Element UI | 2.15.14 | 满足 `^2.13.0`。表单、对话框、抽屉、开关、表格、消息框都用它。2.15 是 2.13 的后续修订，组件 API 一致，修了一些抽屉和选择器的问题 |
| Vue CLI | 4.5.19 | `npm run serve` / `npm run build`。Node 17 以上需要 `NODE_OPTIONS=--openssl-legacy-provider`，脚本里已经带上 |
| Axios | 0.19.2 | 统一在 `src/api/http.js`。成功时拆掉 `{code,message,data}`，只把 `data` 交给页面。0.19.2 有已知安全公告，正式上网前建议升到 0.21 以后；这次按给定主版本保留 |
| ECharts | 5.4.x（`^5.1.2`） | 试跑里数值数据卡的小曲线，标出 T0 |
| vue-i18n | 8.28.2 | 已 `Vue.use`，文案在 `src/i18n/index.js`。业务只有中文，所以只维护 `zh` |
| TypeScript | 3.5.3 | 只检查 `frontend/ts/api-types.ts`。页面组件没有改成 TS，原因见下 |

## TypeScript 为什么没有铺到页面

Vue 2.6 的 class 组件或 `vue-property-decorator` 要额外一套写法，Element UI 2 的类型定义在 TS 3.5 上不完整，属性提示经常是 `any`。把全部页面改成 TS 会拖慢功能对齐，类型也帮不上忙。

因此：

- 页面、路由、Vuex、接口封装用 JavaScript；
- 保存故障、预览表达式这些核心请求体写在 `frontend/ts/api-types.ts`；
- `npm run typecheck` 用 `tsc --noEmit` 检查这份契约。

## 原型能力与组件的差距

### 梯形图

Element UI 没有继电器梯形图。ECharts 的图类别也不适合「串联 = 且、并联 = 或」这种电气图。

处理：后端把组合式解析成展示树（`display`），前端 `src/utils/ladder.js` 自己画 SVG。分组清单用中文释义的分行文本。没有再引入 JointJS、AntV X6 一类库，避免为这一张图带进和 Vue 2 配合不稳定的依赖。

没做完的部分：原型大图里的滚轮缩放、拖拽平移、导出 PNG/SVG。当前梯形图是内嵌 SVG，能看清且/或结构。

### 流程图

同样不适合用 ECharts 或 Element 画。处置步骤有五种形状（矩形、菱形、圆角、六边形、胶囊），箭头上是分支名。

处理：`src/utils/flowSvg.js` 按步骤顺序画形状，并标出去向。分支指向非下一步时写成「转至 序号」。没有引入 LogicFlow / AntV X6：它们的现成示例多数面向 Vue 3，或者会把包体再抬一截，而种子数据里的流程只有几步到十几步，自绘足够读。

没做完的部分：原型那种避免交叉的树状布局、不可达节点直接画在图上的红字（校验结果现在写在流程头的红框里）。

### 零 JSON 表达式编辑

不需要 Monaco。组合式是很短的 `A1 & (A2 | A3)`，用文本框加按钮插入代号即可。语法检查、展开、中文释义、反解析全部走后端，前端只展示返回的规范写法和出错位置。这样前后端不会各写一套解析器。

### 试跑曲线

ECharts 折线图够用。统计值（最小、越限时长等）由后端按原型算法算好，前端不自己重算，避免和 Java 求值分叉。

### 拖拽排序

Element UI 2 没有开箱即用的列表拖拽。步骤顺序改为「上移 / 下移」，调用 `POST /api/flows/{id}/steps/reorder`。语义和拖拽一样：第一位是起点，出口仍按步骤主键连，不因为排序改编号。

### 国际化

vue-i18n 已接入，但手册和原型全是中文，没有第二套语言要翻。字典的中文名来自 `t_phm_dict_item`，不写死在前端。

## 后端组件

| 组件 | 作用 |
|---|---|
| Spring Web | 控制器、校验、全局异常 |
| MyBatis-Plus | 单表 CRUD、分页、逻辑删除。乐观锁在业务里用 `rev` 做 `WHERE rev = ?`，避免和「把可空字段更新成 null」互相打架 |
| PostgreSQL JDBC | 本地和 Supabase。SQL 用 `CONCAT`，不用 `::` 和 JSON 函数，方便以后换金仓 PG 模式 |
| springdoc | `/swagger-ui.html`、`/v3/api-docs` |
| JUnit 5 | 表达式单测、发布校验单测、加载 01+02 的集成测试 |
