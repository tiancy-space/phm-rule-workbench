# 部署说明

后端是 Render 的 Docker Web Service，前端是 Cloudflare 静态资源，数据库先在 PostgreSQL / Supabase 执行脚本，以后再迁人大金仓。

## 数据库

在空库上按顺序执行，不要改 `db/01_schema.sql`：

1. `db/01_schema.sql`：19 张 `t_phm_` 表。
2. `db/02_seed.sql`：示例数据，可重复执行。
3. 只有 Supabase 再执行 `db/05_supabase_only_rls.sql`。它给 19 张表打开 RLS 且不建策略，匿名密钥不能读写。金仓和本地 PostgreSQL 不要执行。

表之间的关系见 `db/04_er_diagram.mmd` 和 `db/README.md`。典型查询在 `db/03_sample_queries.sql`。

### 迁到人大金仓 KingbaseES

PG 兼容模式和 Oracle 模式不是同一套导入步骤。Oracle 模式（`database_mode=oracle`，例如 V008R006C008B0020）看下面的「本地金仓（oracle 模式）部署」。PG 兼容模式仍用 `01_schema.sql` 和 `02_seed.sql`，连接前自行 `SET search_path`，分页保持 `DB_TYPE=postgre_sql`。两种模式都不要执行 `05_supabase_only_rls.sql`。

## 本地金仓（oracle 模式）部署

目标是用户本机的 KingbaseES V8R6，`database_mode=oracle`。实例初始化之后不能再改成 PG 模式。不要去改 `ora_input_emptystr_isnull`，保持默认（空串当 NULL）。应用里本来就把空串收成 NULL。

`db/01_schema.sql` 先原样执行。它用的是 BIGSERIAL、VARCHAR、TEXT、NUMERIC、TIMESTAMP、CHECK、`CREATE TABLE/INDEX IF NOT EXISTS` 和 `POSITION`。这些在金仓手册里有收录，不是已经确认不支持的语法，所以没有另做 `01_schema_kingbase.sql`。若本机建表在 `IF NOT EXISTS`、`BIGSERIAL` 或 CHECK 里的 `POSITION` 上报错，再按报错改一份金仓专用 DDL，不要改这份给 PostgreSQL 用的脚本。

### 执行脚本

用 KStudio 或 ksql 连到业务库，当前 schema 用连接参数 `currentSchema=phm_main` 指定。脚本里不建 schema，也不 `SET search_path`。

1. `db/01_schema.sql`
2. `db/02_seed_kingbase.sql`（不要跑 `02_seed.sql`，里面的 `ON CONFLICT` 在 Oracle 模式会失败）
3. 不要执行 `db/05_supabase_only_rls.sql`

`02_seed_kingbase.sql` 可重复执行：业务唯一键已存在就跳过。试跑测点用 `UNION ALL`，不用 `VALUES (...) AS v(...)`。脚本末尾用 `setval` 把 19 张表的 BIGSERIAL 序列推到 `max(id)`。

抽样查询仍可用 `db/03_sample_queries.sql`。

### 安装驱动 jar

官方 `kingbase8-8.6.0.jar` 不在 Maven 中央仓库，一般在安装目录的 `Interface\jdbc\` 下。JDK 8 用 8.6.0 这版。在 `backend` 目录执行（路径按本机修改）：

```bat
mvn install:install-file -Dfile="D:\Kingbase\ES\V8\Interface\jdbc\kingbase8-8.6.0.jar" -DgroupId=cn.com.kingbase -DartifactId=kingbase8 -Dversion=8.6.0 -Dpackaging=jar
```

驱动类名是 `com.kingbase8.Driver`，Maven 坐标的 groupId 是 `cn.com.kingbase`，两者不是同一个字符串。

`pom.xml` 里的 `kingbase` profile 才引用这个依赖。不带 `-Pkingbase` 的构建（包括 Render Docker）只使用 PostgreSQL 驱动，不需要这只 jar。

### IDEA 运行配置

1. 工作目录：`backend`。
2. 主类：`com.phm.rule.PhmRuleApplication`。
3. Active profiles：`kingbase`（如果另有 `application-local.yml`，写成 `kingbase,local`）。
4. 环境变量按上一节设置。VM options 不用改；仓库里的 Dockerfile JVM 参数只给 Render，本地 IDEA 不要照抄。
5. Maven 目标若用命令行：`mvn -Pkingbase spring-boot:run`。
6. 打开 `http://127.0.0.1:8080/api/health`，`db` 应为 `UP`。再新建一条原子，确认返回的 `id` 大于 0（主键回填）。

## 后端：Render Docker

仓库里有 `backend/Dockerfile`：Maven 3.8 + Temurin 8 编译，运行镜像是 Temurin 8 JRE。进程监听 `0.0.0.0`，端口读 `PORT`（Render 会注入，默认 8080）。

在 Render 新建 **Web Service**，环境选 Docker，根目录或 Docker 上下文指到 `backend/`（Dockerfile 在该目录）。免费实例内存 512MB，闲置后会休眠，文件系统也是临时的，规则数据必须在外部数据库里。

`backend/Dockerfile` 已把 JVM 限制在这个内存里：

- `-Xms64m -Xmx300m`：堆最多 300MB，启动时不要一次占满。
- `-XX:MaxMetaspaceSize=96m`、`-Xss256k`：元空间和线程栈单独封顶，避免和堆加在一起超过 512MB。
- `-XX:+UseSerialGC`：小堆上比 G1 更省本地内存。
- `-XX:+UseContainerSupport`：按容器内存识别上限（JDK 8u191 起已默认开启，这里写明）。
- `-XX:+ExitOnOutOfMemoryError`：真的 OOM 时让 Render 重启，而不是卡死。

这组参数通过 `JAVA_TOOL_OPTIONS` 注入，本地 `java -jar` 不设置时不受影响。

数据库如果用 Supabase 的连接池 Supavisor，选 **会话模式、端口 5432**（不是 6543 事务模式）。会话模式占用真实连接，免费档数量很少，所以 Hikari 配成 `maximum-pool-size: 5`、`minimum-idle: 0`、`max-lifetime: 300000`（5 分钟，短于池子回收连接的常见上限）。不要把池子开到几十，否则一启动就把 Supabase 的连接占满。

环境变量：

| 变量 | 必填 | 示例 |
|---|---|---|
| `PORT` | Render 自动注入 | 10000 |
| `DB_URL` | 是 | `jdbc:postgresql://db.xxx.supabase.co:5432/postgres?sslmode=require` |
| `DB_USERNAME` | 是 | 数据库用户 |
| `DB_PASSWORD` | 是 | 只放在 Render 环境变量，不进仓库 |
| `DB_DRIVER` | 否 | 默认 `org.postgresql.Driver`。金仓改为 `com.kingbase8.Driver` |
| `DB_TYPE` | 否 | 默认 `postgre_sql`。金仓 Oracle 模式改为 `kingbase_es` |
| `CORS_ALLOWED_ORIGINS` | 是 | Cloudflare 站点的源，多个用逗号。例如 `https://phm.example.com` |

健康检查路径：`/api/health`。返回里 `app` 表示进程，`db` 表示当时能否执行 `SELECT 1`。数据库短暂不可用时 HTTP 仍是 200，避免免费实例被探活打死；请看 `db` 字段。

本期不做登录。审计字段只认请求头 `X-Operator`，不传则为 `system`。不要在环境变量里放操作者口令。

接口文档：`/swagger-ui.html`。

## 前端：Cloudflare 静态托管

```bash
cd frontend
export VUE_APP_API_BASE=https://你的后端域名
npm ci
npm run build
```

把 `frontend/dist/` 作为静态站点根目录。路由是 hash（`#/`），刷新不会 404，不需要把所有路径回退到 `index.html`。`publicPath` 是 `./`，资源用相对路径。

`VUE_APP_API_BASE` 只在构建时写进包里。换后端地址要重新构建。不要在前端包里放数据库口令。浏览器只访问后端的 `/api`。
